# Upload Safety

This document covers course material upload controls.

Source files:

- `src/api/services/course_documents.py`
- `src/api/routers/courses.py`
- `src/ingestion/loader.py`
- `src/config/settings.py`
- `nginx.conf`

## Access Boundary

Course material upload endpoints require course teacher access or platform admin access.

Endpoints:

- `POST /courses/{course_id}/documents`
- `POST /courses/{course_id}/documents/zip`

Both endpoints reject uploads while course materials are `queued` or `building`.

## Direct File Upload Limits

| Setting | Default |
|---|---:|
| `document_max_upload_files` | 50 files |
| `document_max_file_bytes` | 25 MB per file |
| `document_max_total_upload_bytes` | 100 MB total request payload |

Files are read in 1 MB chunks. The backend raises HTTP 413 when a configured size limit is exceeded.

## Zip Upload Limits

| Setting | Default |
|---|---:|
| `zip_max_files` | 500 extracted files |
| `zip_max_archive_bytes` | 50 MB archive |
| `zip_max_uncompressed_bytes` | 100 MB expanded contents |
| `zip_max_compression_ratio` | 100.0 |

Nested zip files are expanded up to depth `3`.

Zip handling:

- corrupt zip files are skipped as invalid;
- password-protected zip files are skipped as invalid;
- macOS metadata entries are skipped;
- unsupported files are skipped;
- files beyond `zip_max_files` are skipped;
- files over `document_max_file_bytes` are skipped.

If no supported file is collected from the archive, the backend returns HTTP 400.

## Supported File Types

Supported extensions are defined in `src/ingestion/loader.py`.

| Loader | Extensions |
|---|---|
| `PyPDFLoader` | `.pdf` |
| `Docx2txtLoader` | `.docx` |
| `TextLoader` | `.html`, `.htm`, `.txt`, `.md`, `.rst`, `.csv`, `.tsv`, `.json`, `.jsonl`, `.yaml`, `.yml`, `.xml`, `.sql`, `.py`, `.java`, `.js`, `.ts`, `.tsx`, `.jsx`, `.c`, `.h`, `.cpp`, `.hpp`, `.go`, `.rs`, `.kt`, `.swift`, `.php`, `.rb`, `.sh`, `.css`, `.scss`, `.sass`, `.ini`, `.cfg`, `.conf`, `.toml`, `.log` |

Direct upload rejects unsupported file extensions with HTTP 400.

Zip upload skips unsupported files and returns skipped names in the response.

## File Names and Paths

Direct upload filenames are sanitized by `_sanitize_filename()`:

- path components are removed;
- characters outside `A-Z`, `a-z`, `0-9`, `.`, `_`, `-` are replaced with `_`.

Stored filenames are prefixed with a generated UUID:

```text
<uuid_hex>_<sanitized_filename>
```

Zip member names are used as display names and then pass through the same staging path. Stored disk names are generated by `_stage_raw_files()`.

## Staging Model

Uploaded files are not active immediately.

| Status | Meaning |
|---|---|
| `pending_add` | File is staged for the next rebuild. |
| `active` | File is part of the active material index. |
| `pending_remove` | File is excluded from the next rebuild and deleted after rebuild activation. |

Confirming ingestion rebuilds the course retrieval scope before staged changes become active.

## Reverse Proxy Limit

`nginx.conf` sets:

```nginx
client_max_body_size 100M;
```

This matches the backend default total direct upload limit.

## Not Implemented

These controls are not present in the current code:

- antivirus scanning;
- MIME sniffing beyond filename extension checks;
- per-user upload quota;
- content moderation before ingestion;
- file encryption at rest.
